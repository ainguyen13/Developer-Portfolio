Artisane Daily Publisher

Privacy policy

Artisane Daily Publisher is operated by the owner of the Pinterest account @artisane131. It is a local, single-account tool for publishing content individually selected by that owner. It is not open to other users or customers.

1. Content and instructions supplied by the owner

The owner supplies images, titles, descriptions, alt text, the intended account and board name, and scheduled times. The app keeps these local inputs in a content queue. Each selected Pin has a local confirmation time and a fingerprint of its exact inputs and image bytes. A change to those inputs invalidates the selection. The app does not select or approve Pins automatically.

2. Pinterest API information used during a session

The app requests account information to verify the connected username and reads boards to find a uniquely matching board owned by that account. Returned identifiers are used in memory to address the selected board. A Pin-creation response is checked in memory to determine whether the request succeeded.

The app does not persist API-returned Pin IDs, Pin URLs, profiles, board lists, account attributes, content response bodies or API error bodies. It does not build a Pinterest content cache or archive. When account or board information is needed again, the app calls the API again. A board name and expected username in local configuration are owner-supplied destination instructions, not a saved API response.

3. OAuth credentials

Authentication uses Pinterest's official OAuth authorization flow. The app does not request, collect or use Pinterest passwords or session cookies. The authorization code is used for the token exchange and is not saved to application files or callback logs.

App credentials, OAuth access and refresh tokens, granted scopes and token-expiry values are kept separately on the operator's computer. The credential file is restricted to that local user (mode 0600), excluded from version control, and not included in app output or this website. The app stores only the authentication fields needed to connect and refresh; unrelated fields from token responses are discarded.

Requested scopes are boards:read, boards:write, pins:read, pins:write and user_accounts:read. The four board/Pin scopes are required by Pinterest's published Create Pin contract; account access verifies the owner. The implementation does not use these permissions for advertising, engagement automation, profile changes or editing boards.

4. Local operational state and retention

The app keeps its own local job ID, selected-content fingerprint, confirmation time, attempt ID, local timestamps and status such as pending, publishing, published or uncertain. A published status records successful completion of a local job; it does not contain the returned Pinterest Pin ID or URL. Generic local failure categories are used instead of saved API error content. An uncertain write is stopped for manual review and is not automatically retried.

Owner-supplied content, selection records and local job state remain in the owner's local files until the owner removes them or deletes the queue. Removing a selection prevents a future attempt that has not started; it does not delete a Pin already published. Authentication files are retained for the owner's connection and can be removed at any time. Expired tokens may remain in that local file until replaced or removed; expiry does not automatically erase the file. No Pinterest content-response archive is retained.

5. Destinations and sharing

The selected content and destination identifiers are sent directly to Pinterest through its official API. OAuth credentials are used only with Pinterest's official authentication/API endpoints. The app does not sell API information or send it to advertising, analytics, data-broker or AI-training services. It does not scrape Pinterest or combine information from different Pinners.

This public website is static and hosted on GitHub Pages. It contains no app credentials, sign-up forms, analytics scripts or advertising trackers. GitHub may process routine web-request information to serve these pages under its privacy statement. Pinterest processes uploaded content and account activity under its own privacy policy.

6. Controls and deletion

The owner can cancel individual selections, keep publishing paused, remove local content and job files, or remove the local credentials file. Pinterest app access can be revoked through the owner's Pinterest account settings. Published Pins must be managed separately on Pinterest; deleting local files does not delete them.

Contact ainguyen.forwork@gmail.com for questions or help locating and removing local app data. The operator has no public customer database or separate server-side copy of that local data.

7. Changes and current status

This revision removes persistent storage of Pinterest content API responses and introduces individual Pin selection bound to exact content. The implementation has offline tests; OAuth and live API behavior have not been verified because API access has not been approved. Scheduled publishing remains paused and selecting a Pin does not turn it on. This policy must be reviewed before adding other users, server storage, analytics or another data recipient.
