Choose before publishing

The owner previews each image with its title, description, alt text, destination board and scheduled time. A separate confirmation selects that one Pin. There is no select-all or automatic approval step. Changing the image, content, account, destination board name or scheduled time invalidates the selection.

The owner can cancel a selection before its publishing attempt starts. Selecting a Pin does not resume the schedule. If publishing is later authorized and API access approved, the intended limit is two individually selected Pins per day at 20:00 Asia/Ho_Chi_Minh. Missed days are not automatically caught up.

A narrow Pinterest integration

The prepared code uses Pinterest's official OAuth flow. It checks the connected account and reads the owner's boards afresh to identify one matching destination. It only creates new Pins for individually selected owner-supplied content. The interface does not create or edit boards, modify profiles, manage ads, follow accounts, comment, or collect other people's Pins.

The requested scopes are boards:read, boards:write, pins:read, pins:write and user_accounts:read. Pinterest's published Create Pin API contract requires the four board/Pin scopes; the account-read scope verifies the connected owner. These scopes do not describe additional features offered by this tool.

Data kept to a minimum

Content API responses are used only in memory for the current operation. The app does not save returned Pin IDs, Pin URLs, profiles, board lists, response bodies or API error bodies to disk. Board identifiers are resolved again when needed.

The owner's own content queue, individual selection receipts and local job status are stored locally. OAuth credentials are stored separately in a restricted local file. See the policy for the distinction, retention and controls.
